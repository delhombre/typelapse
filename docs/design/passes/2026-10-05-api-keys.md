# Pass: the account island's API keys, 2026-10-05

## Screen

Ticket #144, decision log `docs/decisions/2026-10-05-next-wave.md` D2. Route
`/app` in a hosted build, desktop and phone shells, light and dark. A signed-in
account makes, copies once and revokes API keys from the account island:

- The entry row in the account panel and the keys view it opens
  (`multimedia/studio-account-control.tsx`, `multimedia/studio-api-keys.tsx`
  and `.css`), mounted by `layout/studio-account-island.tsx`.

Out of scope: the panel's other states (sign in, plan card, cloud copy), which
the export and islands pass settled, and the island's own dark plate.

## Before

The signed-in panel had no keys: identity, allowance, the cloud copy, About and
Sign out (`shots/before/account-1440-dark.png`, hosted build on 5233 against a
throwaway PostgreSQL 16, dark; the keys view is a new surface, so it has no
before). Everything new is built from the panel's own parts: the
`.mm-account-form` fields, the cadence control's segmented plate, the one filled
`.mm-account-primary`, the hairline of the sync section.

## Decisions

Foundations (`emil-design-foundations`) and forms (`emil-forms-and-inputs`):

- The keys are a second view of the panel, reached by a 44px list row between
  two hairlines (key icon, "API keys", chevron), not a section stacked into it:
  the signed-in panel is already about 370px, and ten keys beside the form
  would not fit a 700px window. The view is "Account" (back), the heading, one
  sentence, the form, the list.
- One filled shape per view (DECISIONS D2): "Create key", and "Copy key" once a
  key is waiting. Revoke, Cancel and Done are quiet; the destructive answer is
  outlined in `--mm-danger`, never filled.
- The form is a real `<form>`: Enter submits, the name is validated on submit
  and then on change, beside the field (`aria-invalid`, `aria-describedby`,
  focus on the field), `maxLength` 60, `autocomplete="off"`, `spellcheck` off,
  password managers told to leave it. Fields type at 16px under a coarse
  pointer through `.mm-account-form input`.
- "Expires" is a three-segment choice (Never, 30 days, 1 year) drawn as the
  billing cadence control: `radiogroup` semantics from native radios, arrow keys
  and a focus ring in the accent (D9).
- Copy says what happens in one sentence: "Copy your key now", "It is shown
  once. Anyone who has it can render on your account.", "Revoke GitHub Action?
  Anything using it stops working at once.", "Revoked GitHub Action.", "No keys
  yet. Create one above.". The server's own sentence for every refusal.
- The one copy of a key is shown in a wrapping mono block (`user-select: all`),
  Copy is focused when it appears, a failed clipboard selects the key and says
  so. It stays until Done, also when the panel is closed and opened again; it is
  forgotten on sign-out and on a reload, and never written to storage. A failed
  list load keeps the rows in view and offers "Try again".
- Revoke asks first, inline in the row, focus on the safe answer; Cancel returns
  focus to Revoke; after a revoke focus goes to the heading, and a revoke of the
  key whose secret is on screen takes the secret off screen.

Polish (`emil-ui-polish`):

- Hit areas: 32px controls reach 44px with an `::after` of `inset: -6px -3px`
  (the 8px gaps between neighbours are never crossed); the segments reach 40px
  with the radio itself and 44px under a finger (38px segments, 3px track).
- A Revoke label ends where the panel's content ends (`margin-right: -10px`
  inside a scroller that is 10px wider on each side), so the label aligns with
  the Copy button's edge and the scroller never has sideways overflow.
- Radii by the step for their height: 12px key block, field and track, 9px
  segments inside the 3px track (12 minus 3), 10px for the 32px controls.
- Numbers that change are `tabular-nums` ("Used 3 min ago"); the hairlines are
  the row's `border-top`, at content width.

Craft (`craft-design-engineering`):

- Edge-aware scroll fade: `data-more-above` and `data-more-below` from the
  scroll position switch `--keys-fade-start` and `--keys-fade-end` (registered
  `<length>`, 0 to 18px, 200ms `var(--ease-out)`), so the last row is never half
  hidden and a cut row reads as more to come.
- Icon morph on Copy to Check: blur 4px, scale 0.25 to 1, fade, `springs.snappy`
  (`src/presentation/motion.ts`), in one 14px slot so the label never moves.
- Rows: a new key settles in (opacity 0 to 1, `y` -6 to 0, `springs.snappy`), a
  revoked one leaves faster than it came (opacity to 0, 120ms ease-in, no
  travel) and the rows beneath glide on transforms (`layout="position"`,
  `mode="popLayout"`), never on their height (D8).
- The view arrives with one short slide: `mm-keys-in`, 160ms `var(--ease-out)`,
  opacity and `translateX(8px)`; the account view leaves with nothing.
- A press is `scale(0.97)` on `transform 100ms var(--ease-out)`, separate from
  the 150ms colour timing. Hover keeps the island's 150ms (D4 and `SYSTEM.md`
  Motion), which Craft's hover restraint would shorten: the island is one
  product, so it keeps one hover.
- Interface feedback through the studio's own `feedback()` (muted by the header
  switch): `commit` on a key made and on a key revoked, `success` on copied,
  `error` on a refusal.

| Element | Trigger | Properties | Duration, curve | Reduced motion |
| --- | --- | --- | --- | --- |
| Keys view in | Account, API keys | opacity 0 to 1, `translateX` 8px to 0 | 160ms `var(--ease-out)` | none |
| Copy icon | Copy pressed, 1.6s later | opacity, scale 0.25 to 1, blur 4px to 0 | `springs.snappy` | 0ms |
| Row in | a key is made | opacity 0 to 1, `y` -6 to 0 | `springs.snappy` | none |
| Row out | a key is revoked | opacity to 0 | 120ms `cubic-bezier(0.4, 0, 1, 1)` | 0ms |
| Rows beneath | a row leaves or arrives | `transform` (FLIP), position only | `springs.snappy` | 0ms |
| Scroll fade | scrolling, rows changing | `--keys-fade-start`, `--keys-fade-end` 0 to 18px | 200ms `var(--ease-out)` | none |

## Review verdict

`emil-ui-review`: **Approve with changes**. Should fix, all done:

- Revoking the key whose secret was still on screen left the secret card up:
  the store takes it off screen (test in `api-key-store.test.ts`).
- "Copied" was only on the button: a polite `<output>` says "Key copied".
- The segments were 40px under a finger: 44px under `pointer: coarse`.

Nits left: pressing Done without having copied the key loses it with no
question (a new key is one press away); the rows' "Used" labels are read once
per render and go stale while the panel stays open.

## Open

- `(pointer: coarse)` could not be driven in the headless emulation (the device
  preset changes the viewport and agent, not the pointer media), so the 16px
  field and the 44px segments under a finger are proven by the rules that carry
  them, not by a coarse-pointer screenshot. Needs a device.
- The key rows are not renameable and show no count on the entry row.
- A hover-restraint pass on the island (Craft: frequent hovers instant) would
  be a decision for the whole island, not for this view.
